# Frontend Performance Baseline - 2026-02-09

## Scope
- Project: `AristaConnector/frontend`
- Runtime target: `npm start` (production build)
- Focus pages: `/fleet`, `/devices/[id]`

## Measurement Method
1. Run `npm run build` and record Next.js route size summary.
2. Count expected request volume from polling schedules in code paths.
3. Validate behavior with Playwright E2E after code changes.

## Baseline Before Optimization
Source: production build before this change set.

| Route | First Load JS |
|---|---:|
| `/fleet` | 355 kB |
| `/devices/[id]` | 350 kB |
| `/devices` | 249 kB |

Request volume model (60 seconds, excluding initial page load requests):
- `/fleet`: every 10s, `GET /devices` + `GET /health/fleet` => `6 * 2 = 12`
- `/devices/[id]`: every 10s, `GET /devices/{id}` + `GET /devices/{id}/status` + `GET /devices/{id}/events` => `6 * 3 = 18`

Initial load requests:
- `/fleet`: 2 requests
- `/devices/[id]`: 3 requests

## After Optimization (Implemented)
Source: `npm run build` on 2026-02-09 after this change set.

| Route | First Load JS | Delta |
|---|---:|---:|
| `/fleet` | 215 kB | -39.4% |
| `/devices/[id]` | 210 kB | -40.0% |
| `/devices` | 109 kB | -56.2% |

Request volume model (60 seconds, excluding initial page load requests):
- `/fleet`:
  - health every 10s => 6 requests
  - device list every 60s => 1 request
  - total => **7**
- `/devices/[id]`:
  - poll only status + events every 10s => `6 * 2 = 12`

Initial load requests after change:
- `/fleet`: 2 requests (unchanged)
- `/devices/[id]`: 3 requests (unchanged, but only once; no periodic `GET /devices/{id}`)

## Validation Logs
- Frontend build: passed (`npm run build`)
- Frontend E2E: passed (`npx playwright test`, 6/6)
- Backend API tests: passed (`pytest -q tests/test_health_api.py tests/test_devices_api.py tests/test_collector_client.py`, 17/17)

- API latency p95 under real backend load is environment-dependent and should be captured on a running stack (`postgres + redis + backend + collector`) with browser network traces.
- This document records deterministic request-count changes and verified bundle-size improvements from the implemented code path changes.
